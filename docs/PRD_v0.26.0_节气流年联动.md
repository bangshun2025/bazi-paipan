## 三、v2 功能描述

### 3.1 用户诉求（原话）

> 「将节气和流年关联起来，点排盘时默认出生年的节气，点击流年时，节气区就跟着变。」

### 3.2 行为目标

1. **点排盘（默认态）**：节气区展示**命主出生年**的 12 节（不是系统当前年，也不是点击过的流年）。
2. **点击流年**：节气区**切换**到该流年所在公历年的 12 节。
3. **再点别的流年**：**继续跟随**切换（非一次性）。
4. 第 1 轮的全部要求（大运流年区下方、12 节不含气、四行：月日/时间/节名/干支竖排、双胞胎共享区一块）**全部保留**，联动只改变节气区「展示哪一年」，不改变其版式与内容结构。

### 3.3 交互路径（用户视角）

```
排盘(默认) ──────────────► 节气区 = 出生年 1982 · 十二节
                                  │
点击流年 2031 (格) ───────────────┤ 高亮移到 2031 格，节气区 = 2031 · 十二节
                                  │
再点击流年 2042 (格) ─────────────┼ 高亮移到 2042 格，节气区 = 2042 · 十二节
                                  │
点击某大运列 ─────────────────────┤ 高亮移到该大运首年流年，节气区 = 该大运起始年
                                  │
点击「📍 今年」 ──────────────────┼ 高亮回 nowYear，节气区 = 系统当前年
                                  │
重新点排盘 ───────────────────────┘ 重置：节气区 = 出生年
```

### 3.4 展示结构

节气区在 UI 上维持 v1 结构（.jieqi-section：标题 + 12 列四行网格）。**仅标题中的年份与每列数据随 jieqiYear 变化**，不新增按钮、不新增视图层。

- 标题建议：「`<jieqiYear> 年 · 十二节（立春→小寒）`」。
- 为帮助用户理解「默认出生年」语义，可在标题年份后不加额外说明（排盘结果页顶部已有命主出生年 meta）；如需更强提示，可选在标题加 tooltip「跟随选中流年」——文案细节渲染时定，不影响 AC。

## 四、歧义与裁决（Leader 提出 a–e，产品经理裁决如下）

| # | 歧义 | 裁决结论 | 理由 |
|---|------|---------|------|
| **a** | 出生年后点击流年 → 切换；**再点别的流年是否跟随** | ✅ **每次点击都跟随切换**。点击不同流年 → 节气区年份 = 该流年所在公历年；没有「只联动一次」的语义。 | 用户原话「点击流年时，节气区就跟着变」是持续行为；若只联动一次会造成后续点击流年与节气区不一致，违背直觉。 |
| **b** | v1 默认 = 系统当前年 nowYear vs v2「默认出生年」如何收敛 | ✅ **v2 定稿：节气区默认显示「出生年（输入框的公历出生年）」的节气**；`nowYear` 降级为「大运表初始高亮定位」与「📍 今年」专用，不再作为节气区默认年份。出生年 = 八字排盘输入的生年（公历年，即 render.js data.y）。 | 用户原话明确「点排盘时默认出生年的节气」；出生年是命主八字起点，排盘后先看出生年节气符合「看盘/验证四柱」的心智。系统当前年与命主无关，作为默认无产品价值（仍可通过「📍 今年」查看）。 |
| **c** | 切换流年后，是否保留 v1「当前年高亮/哨兵」逻辑 | ✅ **保留哨兵/防御逻辑；高亮语义分化**：① 大运表「当前年高亮 cur」是**既有功能**（初始定位 nowYear、滚动定位），v2 **不改动**其初始与 📍 今年行为；② 节气区年份是**独立状态 jieqiYear**：默认=出生年，点击流年/大运/「今年」后与高亮同步到选中年份；③ 表外哨兵（年份越界 → 占位/「—」不崩溃）**保留**，判定对象改为 jieqiYear。 | 初始「大运高亮=nowYear」与「节气区=出生年」**有意不同步**：前者回答「命主当下在哪步运」，后者回答「命主出生那年节令如何」，二者初始目的不同（用户显式诉求）。一旦用户点击任何流年/大运/「今年」，两者同步，之后不存在分叉。这是可验收、可解释的产品定义。 |
| **d** | 双胞胎共享区节气块跟随哪个命主 | ✅ **共享区一块节气块，跟随「最近一次被点击的命主流年」**：点击老大侧流年 → 按老大数据换算年份；点击老二侧 → 按老二。**初始（未点击）**：若两命主出生年相同（同卵/龙凤胎同年，绝大多数）→ 显示该出生年；若出生年不同（跨年双子，极少）→ 默认显示老大（第一张卡）出生年。 | 共享区只有一块，跟随「当前操作命主」与用户点击直觉一致（我点谁看谁）；v1「双胞胎只渲染一块」不变。双胞胎点击处理已按卡片归属区分（cardData），年份换算沿用既有规则，实现成本低。 |
| **e** | 联动交互入口在代码层如何落 | ✅ **在现有点击回调里追加「重渲染节气区」即可，不需新增事件委托**。入口 = bindEvents 中 ① `.liu-row .li` 点击（流年）② `[data-dy]` 点击（大运）③ scrollToNow（「📍 今年」）。PRD 只约束行为：这三个入口发生后，若导致选中流年变化，则节气区年份 = 该流年公历年并重渲染。 | 现有回调已统一负责高亮 + 主盘列更新，节气区重渲染是同层副作用，架构师在回调内插入即可（详见 §十一给架构师的 ADR 输入）。 |

**一句话产品规则（可复述、可验收）**：

> 节气区显示「当前节气区年份」的 12 节。节气区年份初始 = 出生年；点击任意流年/大运后 = 该选中流年的公历年；点击「📍 今年」后 = 系统当前年；重新排盘后重置为出生年。表外年份显示占位，不崩溃。

## 五、行为状态机（供架构师与测试对齐）

### 5.1 节气区年份 jieqiYear 状态

| 触发事件 | 大运表高亮 | 节气区年份 jieqiYear | 节气区动作 |
|---------|:---------:|:--------------------:|-----------|
| 排盘完成（初始） | nowYear（既有，不变） | **出生年 data.y** | 渲染 jieqiYear = 出生年 |
| 点击流年 `.li`（data-di=i, data-li=j，i≥0） | 移到 (i, j) | **daYun[i].startYear + j** | 重渲染 |
| 点击运前流年 `.li`（data-di=-1, data-li=j） | 移到运前 (j) | **出生年 data.y + j** | 重渲染 |
| 点击大运列 `[data-dy=i]` | 移到 (i, 0)（既有 hiLn 行为） | **daYun[i].startYear** | 重渲染 |
| 点击「📍 今年」scrollToNow | 移到当前大运/当前流年 | **nowYear** | 重渲染 |
| 重新排盘 / 切换命主 / 切换双胞胎模式 | 重置为 nowYear | **出生年（对应命主）** | 重渲染 |

> 双胞胎模式：上表中「出生年/daYun」均取**触发点击所在卡片（cardData）对应的命主**数据；共享区节气块据此重渲染。初始 = 老大 cardData.y（若同年则等价两命主）。

### 5.2 年份换算与既有代码一致（非新算法）

- i≥0 流年：`year = daYun[i].startYear + j`（与 updateCardDyLnColumns 中 lnYear 同式）。
- 运前流年（di=-1）：`year = cardData.y + j`（与 updateCardDyLnColumns di===-1 分支同式）。
- 该换算为**公历年**，直接作为节气取数年份（节气数据源按公历年组织，见 v1 §4.2）。

### 5.3 数据渲染规则（沿用 v1，参数化年份）

- `buildJieqiHtml(jieqiYear)`（v1 已实现的渲染函数保持契约不变：`year` 入参即节气区年份）。
- 立春…大雪取 `jieqiYear` 年；小寒取 `jieqiYear+1` 年（D2 不变）。
- 表外哨兵：`jieqiYear < 1000` 或 `jieqiYear > 2101` → 整块占位「节气数据仅支持 1000-2100 年」；`jieqiYear = 2100` 时小寒列 `null` → 该列「—」+ 标题轻提示（D4 不变）。

## 七、边界与异常（v2 补充）

| 场景 | 行为 |
|------|------|
| 出生年 = 2100（输入上限） | 默认节气区：立春…大雪正常，小寒(2101)越界 → 该列「—」+ 标题轻提示；不崩溃 |

## 八、非目标（v2 新增明确不做）

- **不做**年份选择器/下拉（联动只通过点击流年/大运/「今年」触发）。
- **不做**节气块点击自身可交互（仍纯展示）。
- **不做**节气块跟随「鼠标悬停」流年（只有点击才联动）。
- **不做**保持点击流年时节气区横向滚动位置（见 §七，P2）。
- **不做**跨年双子初始展示 UI 特殊标注（见 §七，P2）。
- v1 §八其余非目标（不做气、不做农历/五行/神煞附加、不引依赖、不改算法表）不变。

## 十一、给架构师的 ADR 输入（v2 补充）

1. **jieqiYear 状态管理**：建议作为渲染上下文局部状态（如 `container._jieqiYear` 或 RENDER 命名空间字段），初始化 = data.y；点击回调更新后调用「更新节气区」函数（等价 `scope.querySelector('.jieqi-section').outerHTML = buildJieqiHtml(year)` 的封装）。
2. **点击流年换算**：直接复用 updateCardDyLnColumns 已有的年份换算分支（i≥0：`daYun[i].startYear+j`；di=-1：`data.y+j`）——建议把换算提为小函数 `liunianYearOf(cardData, di, j)`，三处（列更新 + 节气区）共用，避免口径漂移。
3. **双胞胎归属**：点击回调已有 cardEl/cardData 判定；节气区更新时取该 cardData 换算年份；共享区（无 .bz-twin-card 上下文时）用 container._paipanData。
4. **重渲染范围**：只替换 .jieqi-section 内部（或整块），不得重建 luck-section / 主盘 chart / 破坏事件绑定；注意避免 buildJieqiHtml 后 .jieqi-section 监听（v1 无内部监听，纯展示，无泄漏）。
5. **测试钩子**：保持 buildJieqiHtml(year) 入参化（已实现）；建议暴露 `RENDER.setJieqiYearForTest(year)` 或让 scrollToNow/点击回调可注入 nowYear，便于 T06-T11 稳定断言。
6. **动画/滚动**：节气区重渲染后横向滚动复位最左（新年份从头看）；若需平滑可后续增强，不阻塞本版。
