- 日期：2026-11-07

## 一、为什么识别不出来

不是措辞问题，是判据缺口：

| 说法 | 旧引擎 | 原因 |
| --- | --- | --- |
| 日干在流年中有根 | 认不出 | 通根判据只在命局地支里找，流年干支根本没进 ctx |
| 日干在大运中有根 | 认不出 | 大运只在渲染层用，造盘引擎没接 |
| 日支藏干本气在流年透出 | 认不出 | 「透」只在「藏干→命局天干」之间判，命局之外的天干（流年/大运）不在口径内 |

## 二、这一版做了什么

1. **外部柱进 ctx**：`extOf(full, anchors)` 给出 `{ ly: 流年, dy: 大运 }`。流年用 `liuNianJZ(year)`；大运用该盘 `daYun` 里流年所落的那一步。
2. **锚点规则**（写进 UI 提示与证据）
   - 流年：缺省＝今年（2026 丙午）；`2028年流年` 指定公历年；`32岁` 指定虚岁（出生年＋虚岁－1）
   - 大运：缺省＝流年当年所行那一步；`第3步大运` 指定步数
   - 锚点在分句前抽取并从文本抹掉，避免「第3步」被当成「有根 3 个」
3. **通根加 `where`**：`liunian | dayun | both`，把搜索池换成流年/大运地支；`pos` 缺省 2（日干）。
4. **新判据 `touc`**：某柱藏干透到流年/大运天干，`layer = ben|zhong|yu|any`，`to = liunian|dayun|both`。
5. **口径裁决修复**：「2028年流年日干在大运中有根」里流年只是年份定语，判据对象取紧跟「在/于/入/走/逢」的那根柱。修复前被误判成 both，还给出了「大运无土 → 有根」的自相矛盾证据。
6. **证据逐字回显**：
   - `日干丙（火）在流年2026 丙午（午藏丁己，见丁） → 有根`
   - `日支巳藏丙庚戊，本气丙 → 流年2026 丙午 天干取丙，透出`
   - 大运缺柱（未起运/超出范围）：判据不成立，不出盘，不硬猜
7. **AI 通道同步**：系统提示词补 `where` / `touc` / `lyYear|lyAge|dyStep` 与四条示例；`genAiNormalize` 补默认值。

## 三、口径边界（明说，不藏）

- 「有根」沿用命理通根口径：天干五行在该地支藏干里出现同五行即算（本气/中气/余气同权），一支算一处。
- 藏干用标准 `CANG_GAN` 三层；双胞胎柱的特殊分层不参与造盘判据。
- 流年缺省＝今年，不是「任意一年」；大运缺省＝流年所行那一步，不是「任一步」。要换口径就在句子里写年份/虚岁/第几步。
- 大运按候选的真实出生时刻排（起运精确到小时），所以扫描带外部柱时会走完整排盘，比老判据慢一点（见性能）。

## 六、性能

- 带外部柱的判据需要按候选时刻完整排盘（大运随出生时刻，起运精确到小时）：`paipan` 均值 0.009ms。
- 实测：双透口径（较稀有）745 个候选 / 12ms；单口径多为 1–3ms 内命中。
- 不带外部柱的老判据仍走原来「一日一盘 + 五鼠遁补时辰」的快路径，速度不变。
