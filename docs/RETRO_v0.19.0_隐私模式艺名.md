## 二、顺畅环节（应保持的做法）

### 2.1 需求根因清晰，PRD 决策结构完整
- PRD 从「上课投影/共享屏幕真名泄露」这一真实场景出发，需求动机明确，验收条件可测。
- 5 个决策点均给出方案对比表 + 明确推荐 + 否决理由（如「只显示艺名」vs「小名/艺名」、
  降级链三级、默认开启 + 持久化双保险），为下游减少歧义。
- AC 清单（AC1-AC13 + AC7b）粒度合适，测试师可直接逐条核验。

### 2.2 架构评审兜底机制生效——拦截了真名泄露隐患
- PRD 决策 4 曾判断「龙凤胎视图不显示姓名、无需改动」，架构师在 ADR-005 中对照源码
  （render.js L1219 实际渲染 `<b>d1.name</b>`）修正为**纳入脱敏**。
- 若未被拦截，龙凤胎排盘时老大的真名会直接上屏，隐私目标整体落空。
- **启示**：涉及「某处是否显示姓名」的代码判断，PRD 阶段就应 grep 源码确认，架构复核不可省。

### 2.3 显示逻辑单点收敛（getDisplayName）
- 架构决策把散落的 displayName 拼装收敛为 `ARCHIVE.getDisplayName(a)` 统一函数，
  隐私关闭分支保持 v0.18.0 逐字一致、隐私开启走降级链——从结构上杜绝「漏改一处」。
- 实现后编程师又做了全库残留扫描（`.name` 残留均为数据层），双保险。

### 2.4 数据层与显示层严格分离
- `data.name` 始终保留真名，仅显示层替换；`bz_archives_v2` 键不变、`yiming` 可选零迁移。
- 隐私功能不污染排盘计算与档案数据，回退/降级行为确定，风险面被控制得很小。

### 2.5 编程师自测充分且可验证
- 单元断言（15 条）+ 浏览器冒烟 + 字节级一致性验证 + 语法检查 + token 齐备检查，
  多角度自证，测试师接手时有明确起点。

### 2.6 测试验收全面、证据可追溯
- 14 条 AC 逐条给实测证据（含 DOM 断言、localStorage 直读、confirm 拦截原文）；
- 代码级核对甚至发现「回收站也脱敏」这一超出 PRD 范围的正确覆盖；
- 测试数据测试后清理，不留脏数据；
- 隐私关闭分支回归（AC4/AC6）单独验证，确认与 v0.18.0 行为一致。

### 2.7 发布记录完整、版本真相源唯一
- 版本号以 `standalone.html` 版本注释为唯一真相源，tag/CHANGELOG/部署验证齐全；
- 线上实测含隐私开关、艺名、真名保留等关键点，发布即证明。

## 三、可改进环节

### 3.1 内置回归集未随新功能增长（测试师提出，本轮唯一改进项）
- **现状**：`?test=1` 内置回归仍为 199 条原断言集，页面无任何 yiming/艺名/已隐藏 相关断言；
  隐私逻辑目前靠人工冒烟覆盖。
- **风险**：隐私逻辑是「显示层」改动，后续任何涉及显示名/档案列表/排盘标题的改动，
  都可能悄悄破坏脱敏且回归集无法发现——而隐私破坏的代价是真名泄露。
- **建议**：下版本（v0.19.1 或 v0.20.0）在回归集中补充隐私断言：
  - AC1 对应：无 localStorage 时 `getPrivacyMode()===true`（默认开启）；
  - AC3 对应：getDisplayName 降级链（艺名→小名→匿名、纯空格 trim、旧档案兼容）；
  - AC6 对应：隐私开启时页面不含指定真名、关闭时恢复「小名 / 正名」格式。

### 3.2 显示点清单是「人工核对」而非「可执行检查」
- 本轮 17 个显示点靠清单逐点核对 + grep 残留扫描，质量高，但依赖当轮人肉执行；
- **建议**：把「隐私开启时页面不含真名」沉淀为一个通用断言/测试页检查器，
  未来新增显示点可自动兜底（与 3.1 同源，可合并落地）。

### 3.3 PRD 阶段代码现状核验不够严谨（被架构评审兜住）
- 龙凤胎判断与代码不符，说明 PRD 对「某处显示/不显示姓名」类断言未先核对源码。
- **建议**：PRD 中凡涉及「代码某处现状」的描述，写前 grep 确认；
  同时**保留**「架构师复核 PRD 代码判断」机制——本轮它抓住了真 bug，不可因流程变顺而省略。

### 3.4 发布环节偶发问题：GitHub Pages 不自动构建
- 首次 push 后 pages build 未自动触发，靠推空提交强制触发（已知解法）。
- **建议**：在发布流程记录该问题与解法，后续发布可预判，避免发布时临时排查。

### 3.5 构建同步机制易被误解（非本轮缺陷，流程提示）
- `build_modules.py` 实为 v0.16.0 的单向迁移脚本，并非「模块→内联」常规构建器；
  实际靠「整体替换 6 个 script 块 + diff 校验」完成同步。
- 本轮字节一致性校验严格（standalone.html == index.html，6 块逐字节一致），没有出问题；
  **建议**：在 README 或 ADR 中明确标注该机制，防止后续维护者误用迁移脚本。

## 四、对后续版本的启示

### 4.1 短期（v0.19.1 若出）
1. **补隐私回归断言**（3.1）——成本低、收益高，建议优先做；
2. 若涉及隐私相关改动，把 3.2 的通用检查器一并落地。

### 4.2 中期（v0.20.0）
1. **隐私视觉提示增强**：PRD 曾建议隐私开启时在档案面板显示「隐私模式」小字提示，
   本轮未实现，可作为体验增强项评估；
2. **16 孩预置档案补艺名**：当前靠降级链兜底（小名→匿名），若邦顺课堂需要更顺滑的
   指代体验，可批量补充艺名（产品侧决策）；
3. **回归集基线化**：建议后续每个版本强制「新功能对应新断言」——AC 与断言一一对应，
   避免再次出现功能上线但回归集零增长的情况。

### 4.3 机制层面（长期）
- **「架构师复核 PRD 代码判断」应固化为标准动作**：本轮价值证明，该环节是隐私/数据安全类
  功能的质量闸门；
- **显示类功能统一走单点显示函数**：getDisplayName 模式可复制到后续所有涉及「展示名」的功能；
- **发布预检清单**：加入「pages 可能不自动构建，需准备空提交强制触发」项。
