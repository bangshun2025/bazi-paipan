## 1. 执行主体与「两态」模型（第一前提）

| 态 | 入口 | `storeKey()` 实返键（xingyao.js:28–31） | 说明 |
|---|---|---|---|
| **测试态** | 页面 URL 带 `?test=1` | `bz_xingyao_map__test`（= `XINGYAO.XY_TEST_KEY`） | 全部自动化断言在此态执行；键隔离，不碰真实数据 |
| **真实态** | 页面 URL 不带 `?test=1` | `bz_xingyao_map`（= `XINGYAO.XY_STORE_KEY`） | 仅人工冒烟用；**未经允许不得在自动化里读写真实键** |

**源码级硬事实（已核 `xingyao.js`）**：

```js
// xingyao.js:28-31
function storeKey() { return xyIsTestMode() ? XY_TEST_KEY : XY_STORE_KEY; }
// loadFromStorage() 第一步即 lsGet(storeKey())
// resetTestStore()（:414）只删 XY_TEST_KEY 及其 _corrupt_/.backup 派生键，绝不触碰 XY_STORE_KEY
```

⇒ **测试态下模块只读 `__test` 键，永不读真实键**。任何「往真实键预置数据来测」的写法在测试态都拿不到数据（白写），且会污染用户真实配置（纯风险、零收益）。

## 2. 硬前提（★违反即断言无效 / 假绿 —— 必须逐条落实）

### HP1 ★ T09 / AC19 的取样必须在「弹层可见态」

- **要求**：`getComputedStyle(tr).display === 'none'` 断言之前，**必须** `XINGYAO.openSettings()`，并断言 `#xySettingsOverlay` 含 `.show`。
- **依据**：祖先 `display:none`（弹层未打开）时，子元素 `getComputedStyle` 的 `display` 失真，同一条断言会随取样时机在**假红 / 假绿**之间摆动（PRD AC19 核验方式 r4；架构师实测确认）。
- **正确写法**：

```js
XINGYAO.openSettings();                                     // ← 前置，令弹层 .show
assert(document.getElementById('xySettingsOverlay').classList.contains('show') === true);
XINGYAO.filterRows('甲申');
const trHide = tbody.querySelector('tr[data-gz="甲子"]');
assert(trHide.hasAttribute('hidden') === true);             // 断 ①
assert(getComputedStyle(trHide).display === 'none');        // 断 ②（证明兜底 CSS 生效 / E18）
```

- **反例（禁止）**：未开弹层直接 `getComputedStyle` 取隐藏行 display。

### HP2 ★ AC11「筛选不丢草稿」必须走真实保存链路（P0）

- **要求**：不能只断 `collectDraft()` 返回值。必须：**改可见行 + 改隐藏行 → 输入筛选词 → `save()` → `XINGYAO.getAll()` 全量 60 键深度比对**，确认被隐藏行原值不丢。
- **两条都要留**：
  - **T10 守机制**：`hidden` 行仍带 `tr[data-gz]` 且其值进入 `collectDraft()`（AC11 机制侧守护者）。
  - **AC11/T04 守结果**：端到端保存后 `getAll()` 60 键完整、隐藏行值不变。
  - 只留一条时：机制层出错（有人把 `collectDraft` 改成可见性过滤）要等到端到端才暴露。
- **依据**：PRD FR2.5 铁律 + ADR §5.2 红线 + AC11（本版 P0）。

### HP3 ★ 可见行计数口径唯一：`tr[data-gz]:not([hidden])`

- **要求**：AC01 / AC10 及一切「可见行数」断言，一律用 `querySelectorAll('tr[data-gz]:not([hidden])')`。
- **禁用**：`:visible`、`offsetParent`、`getBoundingClientRect`、`offsetHeight>0` 等**依赖布局/滚动**的可见性判定 —— 行高与父容器滚动会让结果不稳定。
- **依据**：PRD AC01 核验方式；ADR §3.6（显隐机制 = `hidden` 属性）。

### HP4 ★ AC05 / AC06 的前置动作与跨角色协同

- **(a) 前置**：断言前先 `XINGYAO.openSettings()` 触发 `renderSettings()`，否则 `tbody` 还是上一次的内容；表头用改造后的下标 `[1]`（`thead th[1]`）。
- **(b) 协同项（依赖编程师）**：PRD §2.6 要求同步改写的两条 v0.29 断言必须先完成，否则同一次 `?test=1` 里新旧期望值互相打架，会出现「改对了反而红」的**假红**：
  - `main.js:1787` 表头期望：`'纳音五行'` → `'纳音'`；
  - `main.js:1796–1803` T06 抽样 12 项：单字五行 → **完整纳音名**。
- **(c) 真缺陷哨兵**：`v0.29 T05:数据行=60` **不应**变化（栏头在 `tbody` 外、不带 `data-gz`）—— 若它变红，说明栏头/容器实现有误（真缺陷），不是测试错。

### HP5 ★ AC15 持久化兼容的**测试态写法**（键名隔离、零污染）

> ⚠️ **前置说明**：曾短暂出现「预置真实键 `bz_xingyao_map` 来测兼容」的错误口径，**已作废，不得采用**。原因见 §1：测试态只读 `__test` 键。以下为正式口径。

- **原理**：AC15 验的是**数据结构兼容**；而键名由 `storeKey()` 决定、与版本无关。v0.29 与 v0.30 载荷结构**完全相同**（`schemaVersion:1` + `map{gz:{name,system}}`，无新增字段），故「旧结构」无需特制 —— 直接用 v0.29 真实导出 JSON，或手写同结构皆可。测试态把它写进 **`XY_TEST_KEY`** 即可。
- **正确写法（保留隔离、零污染）**：

```js
// 预置 v0.29 结构到「测试隔离键」
localStorage.setItem(XINGYAO.XY_TEST_KEY,
  JSON.stringify({ schemaVersion: 1, updatedAt: '<ISO>',
                   map: { '甲子': { name: '旧名', system: '旧系' } } }));
XINGYAO.init();                       // 或 location.reload()
// 断言：该格回填 = 旧名 / 旧系；XINGYAO.XY_SCHEMA_VERSION === 1；
//       getAll() 键数 = 60；未产生任何 *_corrupt_* 备份键
XINGYAO.resetTestStore(); XINGYAO.init();   // 收尾
```

- **E12（损坏数据）同理走隔离键**：备份名 `bz_xingyao_map__test_corrupt_<ts>`，全程不碰真实键（v0.29 T08 已覆盖）。
- **不做「真实键人工冒烟」**（PM 与架构师一致建议）：它验的是同一段 `loadFromStorage()`，收益近零、风险是污染真实数据。若确需验真实键路径，只能在不带 `?test=1` 的页面人工冒烟，事后 `removeItem('bz_xingyao_map')` 并断言清理成功 —— **本版不建议做**。

### HP6 ★ AC25 / T15「筛选态栏位正确性」的适用域与判定口径（r7 新增·Leader 裁定 A，PM 备案）

- **(a) 适用域（必须遵守）**：**AC25/T15 仅在视口 `≥1280px`（三栏态）下判定**；`<1280px` 走 AC23 **单栏纵向降级**（已知行为 **L**），**AC25/T15 不适用**。
  - 原因：窄屏 <1280px 三栏头**纵向堆叠**，按「行 `left` 落在栏头**水平**区间内」判会**假红**（AC25 的几何判据隐含三栏前提）。
      - **边界说明（Leader 采纳）**：**1280 属三栏态**（恰命中 `@media(min-width:1280px)`）⇒ **AC25/T15 在 1280 适用**；**`<1280px`（如 1024、375）走 AC23 降级**（单栏纵向，记已知行为 **L**）。
    - 语义与 FR3.7 / AC23 一致，**判定口径零变更**；此条为**测试执行前提**，不爬升 PRD 版本（r7 保持终冻，Leader 裁定 A）。
- **(b) 判定方式（必须为几何判定）**：对**每条**可见行 `tr[data-gz]:not([hidden])`，其 rendered `left` 必须落在**其 `data-xy-group=N` 对应栏头** `.xy-group-title[data-xy-group="N"]` 的水平区间 `[head.left - 8, head.right + 8]` 内（**容差 ≤8px**）。
  - 覆盖：搜「己」→ 组 1/2/3 各行分别落栏 1/2/3（**不是 6 行全挤栏 1**）；搜「癸亥」→ 落栏 3；搜「甲子」→ 落栏 1。
- **(c) 严禁（本轮最易写歪处）**：**禁用 `[data-xy-group]` 计数判定** —— 缺陷实现下计数仍可能是 **2/2/2**（DOM 属性未变），属**假绿**；计数只可作辅助交叉核对。
- **(d) 断言禁则（r7 FR3.4.3 / D20）**：断言只锁**钩子 / 行为 / 几何**；**禁止**锁 computed `grid-auto-flow` / `grid-template-*` 的字面值（锁死实现）；不需要 `nth-child` 式定位。
- **前置**：`openSettings()` 且 `#xySettingsOverlay.show`（同 HP1）；`await document.fonts.ready` / rAF 后取样。

### HP7 ★ C3 表头几何断言的媒体查询归属与窄屏边界（C8 前提）

> **口径更正（架构师第 24 轮 + Leader 第 44 轮裁定，覆盖早期「<1280px 保持默认 table/thead」的错述）**：`tbody` 已是 grid（本版三栏实现前提）⇒ 表格里只剩 `thead` 一个行组参与表格布局 ⇒ 浏览器**按内容收缩** thead，**列宽不再由列模板决定**。实测：零覆盖 thead 宽 **230**（≠883.6）、th **64/38/64/64**、delta **[0,4,−38,−347.8]** ❌；强制 `display:table-header-group` 亦 ❌（thead 272 ≠ 754、delta [0,0,0,−241]）。

- **现行 recipe（最终）**：
  - **base（全宽度生效，不带媒体查询）**：`.xy-table thead{display:block}` + `thead tr{display:grid;grid-template-columns:56px 76px minmax(0,1fr) minmax(0,1fr);gap:4px}`；
  - **仅 `thead{width:calc((100% - 32px)/3)}` 进 `@media(min-width:1280px)`**（`1/3` 栏宽只在三栏态成立；窄屏单栏行占满整表宽）。
  - ⚠️ **不得**把「`display:block` + 同列模板」也塞进媒体查询，**也不得**退化为默认 `table-header-group`。
- **适用域纪律**：**C8 仍只在 ≥1280px + 60 行全显态判定**；窄屏走 **N6 / AC23**，**不因窄屏也已对齐就扩 C8 到全断点**。
- **窄屏（<1280px）可断言形式 = N6**（架构师第 24 轮升级）：`thead` computed `display === 'block'`、**`thead` 宽 = 数据行宽**、`th[i].left` 与任一可见行字段 `[i].left` 偏差 **≤12px**、`th[i].width ≥40px`、**弹层内无横向溢出**（页面级 `div.luck-table` 既有例外不计）。实测（真实 `index.html` 880×682 干净加载）：thead 宽 **754 = 行宽**、th **56/76/305/305**、delta **[0,0,0,0]** ✅。
- 依据：Leader 第 17/21/44 轮；架构师第 19/24 轮 recipe；ADR §15.3 C3。

## 10. 经验教训（v0.30.0）

> 本章由产品经理（worker_cd305ff0）供稿、Leader 采纳为**本编排流程改进第 1/2 条**，归测试侧归档；**L2 引文逐字保留**（Leader 将在最终交付总结中引用其原文），事实与数字未改。

**L1｜大改口径后必做全文一致性审计（本编排流程改进第 1 条）**
用户口径级变更后，文档存在**大面积残留**风险。案例：r5 把「分三组」从纵向堆叠纠正为**三栏同屏并排**后，PRD 单次大改遗漏 **12 处**残留（测试师核出 7 处 + PM 自查 5 处），经 r6 全文勘误才归零。
→ 规则：**口径级改动后，必须对全文做一轮关键词对撞 / 残留扫描，再宣告版本冻结。**

**L2｜数量类断言必须配几何判据（本编排流程改进第 2 条，PM 提出、Leader 采纳）**
> 凡「结构数量类」断言（`=N`、计数、存在性）的**相邻几何/视觉属性发生变化**时，必须配一条**几何判据（标称值 + 容差 + 下限值防塌缩）**，否则该数量断言可能成为**假绿来源**。

案例 **C3（共享表头几何对齐）**：`thead th`=4 的断言在表头 **等分铺满全宽**（各 286px，`th.left` = 175/467/759/1051，与第 1 栏列模板 x = 175/235/315/435.3 偏差 **[0, 232, 444, 615.7]px**）时**依然全绿**，而「纳音」标签实际悬在**第 2 栏干支列**上方 —— **门禁绿、视觉错**。补几何判据后缺陷可捕获（C8：① `thead th`=4；② `th[i].left` 与第 1 栏首条**未隐藏**行第 i 字段偏差 **≤12px**；③ **`th[i].width ≥ 40px`**）。

**L3｜修法本身也有假绿通道：下限值是必要项，不是冗余项**
C3 的修法（表头收窄到一栏宽 + 复用列模板）若**漏写/未显式化宽度基准**，两个 `1fr` 轨道会**塌成 2px**：隔离样本实测 `th = [18,56][74,76][150,2][150,2]`；真实页面 C 变体偏差 **392.7px**（「纳音」跑到栏 3 位置）。此时 **`th` 仍 = 4、`left` 仍落在栏 1 区间** ⇒ 只断「数量 + 区间」会**二次放过**。
→ 通用化：**验证「修法」时的假绿风险不低于验证「现象」时** —— 修法生效前后都必须存在能区分「修好了 / 修了但坏了」的判据；几何判据务必含**下限值**。

**L4｜几何量的采样前提（对应 E23）**
几何断言必须在被测元素**可见态**下取样（`openSettings()` + 弹层含 `.show` + `fonts.ready`/rAF 后）。弹层未开时 `scrollHeight == clientHeight == 0` 之类的比较恒真 ⇒ **必然假绿**；同理，禁用 `getBoundingClientRect` 判「是否在视口内」。
