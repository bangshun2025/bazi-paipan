## 记录 key 设计（备忘）

- 已存档组合：`bz_hepan_notes_<合盘id>`（删除合盘连带删除）
- 未存档组合：`bz_hepan_notes_fp-<entriesSig>`（稳定指纹）
- 存档时自动把 fp 记录迁移到 id key；openHePan 恢复后 refreshCmpRec 按 id key 读

## 关键修复

1. **saveFromCmp 覆盖改名静默丢失（产品 bug）**：`exist` 来自 matchHePan 内部另一次 `getHePans()`，与本函数的 `list` 是两份数组的两份引用，`exist.name = name` 改在已丢弃数组上。改为按 exist.id 在同一 list 内定位改名。触发条件：同组合第二次保存时改名——此前无覆盖场景 UI 测试。
2. **hepan 对 ARCHIVE 的启动窗口期守卫**：archive.js 内部引用裸 `APP`，`window.APP` 挂载（main.js IIFE 尾）前调用 getFormData/getArchives 会 ReferenceError（?test=1 断言页必炸）。hepan.js 统一走 archGetFormData/archGetArchives 包装（typeof + try/catch 兜底 null/[]）。
3. **renderCmpTrack 自愈与假档案 id**：对比轨渲染会剔除档案库中不存在的 id 并回写（alive 过滤），断言造的 `tst-arch-1` 必须**真实写入档案库**，否则 HP04/HP12 的组合被清成 [current]。T-HP 段首注入两条测试档案，finally 还原整个档案库。
4. **check-release 切段硬约束**：头注释必须 `/* 八字排盘 vX.Y.Z — hepan.js */` 完整结尾（`src.find('— hepan.js */')`），描述文字挪到第二行独立注释。
5. **sync-module-inline.py 方向**：默认 `--apply` 是内联→外部（回滚方向！）；外部→内联必须 `--from-external main --apply`。hepan 不在 5 核心模块清单，需 /tmp/hepan_inline_sync.py 手动同步两处内联段。
