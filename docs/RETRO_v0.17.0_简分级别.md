## 三、问题分析

### 3.1 TC-10 龙凤胎卡片初始 L0 状态 Bug

**现象**：龙凤胎模式首次排盘后，L0 默认状态下所有扩展行（纳音/纳运/空亡/神煞）均可见。点击一次按钮后恢复正常。

**根因**：`renderTwinCardsHtml()` 和 `renderLongFengCardsHtml()` 中的 `<table class="chart">` 未改为 `<table class="chart level-0">`，而 `renderChart()` 单人模式已正确改为 `level-0`。

**为什么会产生**：

这是典型的「多渲染路径遗漏」。架构师在 ADR §3.3 中**明确指出了三处**需要将表格初始 class 改为 `level-0`：
1. `renderChart()` — 单人模式 ✅ 已改
2. `renderTwinCardsHtml()` — 双胞胎 ❌ 遗漏
3. `renderLongFengCardsHtml()` — 龙凤胎 ❌ 遗漏

而且在 ADR §4 风险矩阵中，架构师已经将「龙凤胎卡片 mainRows 行序遗漏」标记为**中风险**并给出了缓解措施。即便如此，实现阶段还是漏了。

**深层原因**：ADR 的修改方案分成了 9 个小节（§3.1–§3.9），编程师在按节实现时，可能在 §3.5（mainRows 行序）和 §3.6（buildCardHTML）投入了大量精力处理复杂的索引重排，导致 §3.3 末尾的一句话级改动被忽略。

### 3.2 修复过程

修复方案简单：给龙凤胎/双胞胎卡片的 `<table>` 加上 `level-0` class。测试师虽然未单独记录修复后的复测结果，但最终结论为 12/12 PASS，表明问题已解决。

## 五、改进建议

### 5.1 【立即执行】引入「实现自查清单」

建议在编程师完成实现后，新增一个自检步骤：逐条对照 ADR 中「精确修改方案」（§3）的每个子节，勾选确认。格式建议：

```
□ §3.1 CSS — 删除 .simple 规则
□ §3.1 CSS — 新增 .level-0/1/2/3 规则
□ §3.2 toggleLevel 函数替换
□ §3.3 按钮 HTML 初始化 — renderChart()
□ §3.3 按钮 HTML 初始化 — renderTwinCardsHtml()   ← 本次遗漏
□ §3.3 按钮 HTML 初始化 — renderLongFengCardsHtml() ← 本次遗漏
□ §3.3 删除 _simpleMode 死代码
□ §3.4 buildPillarRows 行序 — 四柱区
□ §3.4 buildPillarRows 行序 — 三垣区
□ §3.5 renderChart mainRows 调整
□ §3.6 buildCardHTML mainRows 调整
□ §3.7 _applyDLUpdates 单人映射
□ §3.7 _applyDLUpdates 双胞胎映射
□ §3.8 main.js 别名更新
□ §3.9 RENDER 挂载更新
```

架构师在 ADR 中已经天然地把修改方案拆分成了可勾选的子项，编程师只需按这个结构逐项核对即可，零额外成本。

### 5.2 【建议】测试师 Bug 修复后追加复测记录

当 Bug 修复后重新测试时，在对应 TC 下追加一个「修复后验证」小节，不要只改结论数字。这样 RETRO 时可以追溯 Bug 的完整生命周期（发现→修复→验证）。

### 5.3 【观察】ADR 体量增长趋势

v0.17.0 的 ADR 达到 437 行，修改方案拆分为 9 个子节。相比之前的迭代（典型的二态切换），复杂度明显上升。随着项目演进，ADR 会越来越长，编程师逐条对照的认知负荷也会增大。如果未来 ADR 超过 500 行，建议考虑将「修改清单」单独抽取为一个结构化 checklist（如 JSON/Markdown table），方便编程师直接导入 TODO 工具逐项打勾。
