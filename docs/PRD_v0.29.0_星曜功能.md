## 一、需求来源与目标

### 1.1 用户需求原文（逐条保留，不得删减）

1. 盘面新增一行「星曜」，位置在「藏气」行与「纳音」行之间（现行序：主星→干支→藏气→纳音→纳运→星运→自坐→空亡→神煞）。
2. 显示条件：简分级别切到「中」时显示（现有五级：L0极简/L1简/L2中/L3详/L4全，起始级别与更高层级行为按现有分级规则统一设计）。
3. 工具栏「简」按钮之后新增「星曜」按钮，点击弹出星曜设置页面。
4. 设置页面列出四列：六十甲子、纳音五行、星曜名称、来源体系；星曜名称与来源体系初始留空，供用户填写。
5. 填写确认后，甲子与星曜名称/来源体系的对应关系要纳入八字算法规范 `docs/ALGORITHM.md`。写入时机、章节编号、数据存储与生效机制必须在 PRD 中明确。
6. 设置页面需支持修改、清空、还原三功能；还原语义（恢复默认 vs 恢复上次保存）必须在 PRD 中给出唯一确定的定义。
7. 文案统一为「星曜」（原文有一处误写「星耀」）。

### 1.2 需求一句话

在四柱/三垣盘面的「藏气」与「纳音」之间新增一行**用户自定义的「星曜」**（按六十甲子查表的名称 + 来源体系），
在中层级及以上显示；工具栏「简」按钮后新增「星曜」按钮打开设置页（四列 × 60 行），支持修改/清空/还原，
并把「六十甲子 ↔ 星曜名称/来源体系」的对应关系固化进 `docs/ALGORITHM.md`。

### 1.3 目标（本次要达成）

- G1 盘面行序扩展，星曜行落在「藏气」与「纳音」之间，四柱区与三垣区一致（见 D1）。
- G2 分级联动：L0/L1 不显示，L2「中」起显示。
- G3 新增设置入口与设置页，数据可编辑、可持久化、可修改/清空/还原。
- G4 算法规范可追溯：`ALGORITHM.md` 新增星曜章节，且**幂等可重写**。
- G5 文案统一「星曜」。

### 1.4 不在范围（明确声明，避免误扩）

- ❌ **不内置任何星曜体系默认数据**：出厂即全空（见 §7 出厂默认定义），不做预置映射。
- ❌ **不做星曜推演/计算**：星曜名称与来源体系**完全由用户手填**，程序不做任何天文/命理推导。
- ❌ 不改 `ALGORITHM.md` §1–§20 既有章节内容与编号。
- ❌ 不改简分级别 L0/L1/L3/L4 对**既有行**的显示规则；不改工具栏其它按钮。
- ❌ 不改盘面其它行、不改 CSS 主题变量、不改档案/账号/宫位配置等既有功能。
- ❌ 不提交 git、不改 `ext.yml` 版本号、不写 CHANGELOG（留待发布阶段由发布师处理）。
- ⏭ 云端同步（星曜数据上云）**不在本版**，列入 §11 遗留项（D5）。

## 二、现状勘察（代码事实，行号为 2026-09-11 实测）

### 2.1 盘面行序现状

**四柱区**（`render.js` `buildPillarRows()`，`render.js:230–266`）行序为：

```
主星(rs) → 天干(rg) → 地支(rg) → 藏气三层(rh) → 纳音(rn,nayin) → 纳运(rm,nayun)
        → 星运(rm,xingyun) → 自坐(rm,zizuo) → 空亡(rm,kongwang) → 神煞(rm,shensha)
```

**三垣区**（同函数 `sanyuan` 分支，`render.js:269–295`）为同一行序，列为 胎元/命宫/身宫。

> ⚠️ **单人排盘会合并藏气**：`render.js:540` `mainRows.splice(4,2)` 删除中气/余气，只保留一行「藏气」。
> 因此**单人视图**行序为：主星→天干→地支→藏气→纳音→…（与本需求描述一致）。

### 2.2 简分级别（五级）现状

- 常量：`render.js:190` `LEVEL_LABELS = ['极简','简','中','详','全']`；`render.js:191–197` `LEVEL_TITLES`。
- 切换：`render.js:199 toggleLevel()` 对 `.chart` 增删 `level-0..4` 类。
- **显示规则由 CSS 驱动**（`index.html:216–238`，三端各一份）：

| 级别 | 标签 | 隐藏的 `data-row-type`（display:none） |
|---|---|---|
| `level-0` | 极简 | `xingyun` `zizuo` `nayin` `nayun` `kongwang` `shensha` |
| `level-1` | 简 | `nayin` `nayun` `kongwang` `shensha` |
| `level-2` | 中 | `kongwang` `shensha` |
| `level-3` | 详 | `shensha` |
| `level-4` | 全 | （无，全部显示） |

> 结论：分级是**累积展开**语义——级别越高隐藏越少。**纳音行在 L2 起显示**。
> 星曜行位于藏气与纳音之间、且语义与六十甲子/纳音同源，故**纳入同一档：L0/L1 隐藏、L2 起显示**（见 D2）。

### 2.3 工具栏按钮现状

工具栏按钮由 JS 模板动态渲染，`btn-simple`（简分级别按钮）后紧跟 `renderGongWeiPanel()`（宫位按钮），共三处模板：

| 位置 | 场景 |
|---|---|
| `render.js:673` | 单人排盘 top-bar |
| `render.js:1242` | 双胞胎（龙凤胎）top-bar |
| `render.js:1353` | 双胞胎另一分支 top-bar |

模板片段：
```html
<button class="btn-simple active" onclick="RENDER.toggleLevel()" title="…">极简</button>${renderGongWeiPanel()}…
```
> 「星曜」按钮应插在 `btn-simple` **之后、`renderGongWeiPanel()` 之前**（即「简」按钮的紧邻右侧），三处模板均需插入。

### 4.2 交互细节

1. **打开设置页**：点击工具栏「星曜」→ overlay 淡入（`.show`）；焦点进入第一个输入框；`Esc` 关闭。
2. **编辑**：输入即时反映在草稿，**不落盘**；输入框失焦不触发保存。
3. **保存并关闭**：写 `bz_xingyao_map` → 关闭 overlay → 重渲染盘面星曜行 → 顶部轻提示（可选）`星曜已保存`。
4. **清空**：仅清空草稿；若草稿原本为空则不提示。
5. **还原**：草稿回滚为上次保存值；若从未保存过 → 全部置空。
6. **关闭未保存**：等同还原，不弹确认（若架构师倾向弹确认，见 D10）。
7. **行高亮**：已填值的行可加轻微底色（可选，非必须）。

## 五、星曜数据模型与持久化方案（**建议，待架构师确认**）

### 5.1 存储结构（localStorage）

**键名**：`bz_xingyao_map`

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-09-11T07:20:00+08:00",
  "map": {
    "甲子": { "name": "", "system": "" },
    "乙丑": { "name": "", "system": "" },
    "…":   { "name": "", "system": "" },
    "癸亥": { "name": "", "system": "" }
  }
}
```

- **主键 = 六十甲子字串**（`甲子`…`癸亥`，60 项）。稳定、可读、与 `NAYIN` 表键一致。
- **`name`** = 星曜名称（空串 = 未填）；**`system`** = 来源体系（空串 = 未填）。
- **纳音五行不入库**：由 `constants.NAYIN[干支]` 末字**派生**（只读列），避免冗余与漂移。
- **`schemaVersion: 1`**：仿 `bz_gongwei_schema_version` 的做法，便于未来迁移。

### 5.2 备用/防御性键

| 键 | 用途 |
|---|---|
| `bz_xingyao_map` | 主数据（§5.1） |
| `bz_xingyao_map_corrupt_<时间戳>` | 损坏数据备份（沿用 v0.25.0 防静默重置模式） |

### 5.3 生效机制

1. **加载**：页面初始化读 `bz_xingyao_map`（容错解析，见 §8-2）；生成 `RUNTIME_MAP = {干支: {name, system}}`。
2. **渲染**：每一柱 → 取该柱干支 → 查 `RUNTIME_MAP` → 取 `name`（盘面显示「星曜名称」；是否显示来源体系见 D11）。
3. **保存后**：`persist()` → 更新内存 `RUNTIME_MAP` → 调 `refreshXingyaoRows()` 重渲染所有 `.chart` 的星曜行（值级刷新）。
4. **测试态**：`?test=1` 时走独立内存/测试存储（沿用 `gzIsTestMode` 风格），不污染真实数据。

### 5.4 与「六十甲子」的生成口径

```
for (i = 0; i < 60; i++) {
  干支 = TG[i % 10] + DZ[i % 12];      // i=0 → 甲子 … i=59 → 癸亥
  纳音五行 = NAYIN[干支].slice(-1);     // 「海中金」→「金」
}
```
> 与 `ALGORITHM.md §1.5`、`constants.js` 基准一致（1984 甲子、index 0）。

## 七、还原语义（唯一确定定义）

### 7.1 出厂默认

**出厂默认 = 全空**（60 行的「星曜名称」「来源体系」均为空串）。
产品**不内置**任何星曜体系数据。因此「恢复默认」在数值上等价于「清空并存盘」，**不单独设置「恢复默认」按钮**。

### 7.2 术语定义（唯一）

| 概念 | 定义 |
|---|---|
| **已保存值** | `localStorage.bz_xingyao_map` 中最后一次「保存并关闭」成功写入的数据 |
| **草稿** | 设置页打开后编辑中的一份临时副本；打开时由「已保存值」初始化 |
| **修改** | 编辑草稿 → 「保存并关闭」→ 草稿成为新的「已保存值」 |
| **清空** | 将**草稿**的全部输入置空（60×2 个字段）；**不落盘**，需再保存 |
| **还原** | 丢弃草稿，用「已保存值」重新初始化草稿（即**恢复上次保存**） |

### 7.3 唯一结论

> **「还原」= 恢复「上次保存」的值（restore last saved），不是恢复出厂默认（restore default）。**

- 若**曾保存过** → 还原为上次保存值（盘面不受影响，因未保存编辑本就未生效）。
- 若**从未保存过** → 还原 = 全空（此时「上次保存」状态即出厂默认）。
- **未保存直接关闭** → 等同还原（丢弃草稿）。

### 7.4 三功能状态机（可测）

| 初始状态 | 操作 | 结果（草稿） | 结果（已保存/盘面） |
|---|---|---|---|
| 有已保存值 A | 编辑为 B | B | A（不变） |
| 草稿 B | 保存 | B | **B**（盘面更新） |
| 草稿 B | 清空 | 全空 | A（不变） |
| 草稿 B | 还原 | A | A（不变） |
| 草稿 B | 关闭 | — | A（不变） |
| 草稿全空 | 保存 | 全空 | 全空（盘面全「—」） |

### 7.5 被否决方案（留痕）

- ❌ 「还原 = 恢复默认（全空）」：会导致「还原」与「清空＋保存」语义重复，且无法撤销误清空，用户体验更差。
- ❌ 「清空 = 直接销毁已保存数据」（破坏性）：与「还原」冲突（无从"恢复上次保存"），且违反本项目 v0.25.0「防静默重置」的一贯取向。
