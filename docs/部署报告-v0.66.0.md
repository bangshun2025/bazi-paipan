## 背景（本版起因）
用户反馈「分析记录丢了」。取证结论：记录**没有丢**，是取不到——记录键为
`姓名|性别|公历生日|时|分` 的整串指纹，任一位不同（改名、换时辰、改分钟）就成新键，
面板读不到旧内容，表现为空白；而记录只存本机 localStorage，不上云、无导出，
换机或清缓存即永久丢失。

已回收的存量数据（只读快照 + LevelDB 全量版本扫描，无 Time Machine 快照、
云端 `paipan_records` 不含笔记、其他浏览器 0 命中）：
- 现存记录 10 条 / 2750 字，最长潘政熙 873 字、李程 734 字
- 每个记录键仅 1 个版本、0 个删除墓碑 → 无可回捞的更早版本
- 135 条档案中 125 条从未写过记录；6 个键值为空（改名/换时辰后的空壳），不可恢复
- 导出物：`恢复的分析记录/`（10 个 txt + 合集 md），不在本仓库版本控制内

## 本版变更
- `render.js`：`recNoteCandidates(suffix)` 三级取值 —— ①精确键 ②同生日仅时/分不同且
  唯一命中则自动回捞并提示「已按同生日记录恢复（原 hh:mm）」 ③多条或生日不同则用
  `recRenderAlts` 列出同名历史记录（上限 `REC_ALT_LIMIT=6`，含日期/时刻/字数）供点选载入；
  `recKeyParts` 支持 `twin|` 前缀；`recPanelHtml` / `twinRecPanelHtml` 新增 `.rec-alts` 容器；
  `bindRecPanel` 仅在精确键为空时走兜底，`ta._recBound` 防重复绑定
- `archive.js`：`buildBackup()`（app/exportedAt/archives/trash/recNotes）、
  `backupFilename()`（`八字排盘备份-YYYYMMDD-HHmm.json`）、`exportBackup()`、
  `pickImportBackup()` / `onImportFile()` / `importBackup()` —— 导入为**合并式**：
  档案按 id、记录按键，已存在一律跳过，绝不覆盖
- `index.html` / `standalone.html` / `standalone-split.html`：档案弹窗底部
  `#archiveBackupBar`（`#btnExportBackup` / `#btnImportBackup` / `#archiveImportFile` /
  `#archiveBackupHint`）+ `.rec-alts` 样式
- `main.js`：新增 BK T01–T18 共 18 条断言（备份结构、导入合并语义、回捞与候选）
- `scripts/check-release.sh`：KEYS 补 `btnExportBackup` / `btnImportBackup` /
  `archiveBackupHint` / `archiveImportFile`
