# 部署报告 · v0.102.3

发布时间：2026-11-22 15:45（推送完成，Pages 重建约 2 分钟已生效）
范围：单条 fix；上一线上版本 v0.102.2。

## 1. 版本号与 SemVer 判定

**PATCH**（0.102.2 → 0.102.3，缺陷修复）：档案md 打不开（Chrome queryPermission 偶发挂起致 promise 链卡死）。无行为变更，仅超时兜底 + 测试断言适配。

## 2. 根因（CDP 注入逐环探测）

2026-11-22 实报：点「📄 档案md」弹层永远停在「正在同步并读取最新 md……」。

| 探测环 | 结果 |
|---|---|
| `indexedDB.open('bz_sync_db')` | 1ms 正常 |
| `objectStore.get('dir')` | 命中，句柄存在、有 queryPermission 方法 |
| `handle.queryPermission({mode:'readwrite'})` | **永久 pending**（6s 无 onsuccess/onerror） |
| 目录本体 `/Users/feng/人生资产/96-八字档案` | 存在，盘面 md 齐全 |
| `ARCHIVE.syncAll()` | 瞬回 0（内存 `_syncDir` 未建立） |

结论：句柄指向的目录一直在原位，非权限被拒，属 Chrome File System Access 后端偶发失效（句柄反序列化后内部后端不可用）。同日 `getComputedStyle` 将 `flex-start` 序列化为 `flow-start`（SSHX X19 断言失败）亦是新版 Chrome 行为——两个症状同指向 Chrome 自动更新。

## 3. 修复内容

- **archive.js**：新增 `syncPermOf(h, ms)`——`queryPermission` 与 2.5s 超时竞速，超时按 `'prompt'`（需重授）、异常按 `'denied'` 处理；`syncResume` / `syncEnsureDir` 两处调用点替换。效果：点「档案md」最多 2.5 秒给出明确错误指引，不再无限转圈；页面加载 `syncResume` 同样不挂死
- **main.js**：SSHX X19 断言归一 `flow-start` ≡ `flex-start`（左对齐语义不变）
- 恢复路径：点「📁 本地同步」→ `showDirectoryPicker` 拿全新句柄写回 IndexedDB → 一次授权即恢复
