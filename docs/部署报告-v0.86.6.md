# 部署报告 v0.86.6

日期：2026-10-27 ｜ 类型：PATCH（「档案md」打开提速：热路径 ~1.7s → 26ms）

## 需求与诊断

邦顺反馈「打开太慢」。逐环节计时定位：

| 环节 | 实测 | 结论 |
|---|---|---|
| server `/open-file` | 3–5ms | 排除 |
| server `/edit` HTML | 3ms | 排除 |
| 编辑器页面加载（真实 Chrome） | 106ms（资源全缓存） | 排除 |
| **排盘端 `syncAll` 全量同步** | **1578ms**（165 份档案全部重建重写） | **唯一大头** |

根因：`syncWaitIdle` 每次点击都无条件触发 `syncAll` 全量同步——点按钮只是为了打开文件，却每次白付一次全库落盘。

## 变更内容

- **脏检查按需同步**：新增 `_syncDirty` 标志，`syncTouch`（所有档案写路径的入口，含防抖窗口）标脏；`syncWaitIdle` 改为「无脏直接过、有脏才 `syncAll` 并等完（含并发 pending 轮询）」——数据新鲜度不降级，只是不再为无关点击买单
- **快路径定位**：主档名确定（`盘面-姓名.md`），`syncChartFileQuick` 一次 `getFileHandle+getFile` 直取；重名落 `盘面-姓名-<id>.md` 后缀的才回退全目录扫描
- 回归断言跟进：SN17-7/SN20-5 改写为新语义（检查串拆拼防自匹配污染），新增 SN20-6（标脏存在 + 无脏跳过 syncAll 防回归）
