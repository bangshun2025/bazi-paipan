## 三、问题与根因分层

### 问题 1：P0-01 未登录绕过排盘守卫（AI 录入入口）— ✅ 已闭环

- **事实链**：AC08 守卫仅包装 `APP.doPaipan`；AI 录入走 `doAiParse` 内部直连裸 `doPaipan()` 绕过守卫 → 未登录用户可通过 AI 录入排盘，云端记录归属不可溯。
- **根因分层**：
  - 直接层：守卫覆盖面不全——只包 APP 主入口，未包 doAiParse 调用链与 RENDER 直连入口（togglePrivacy 等）；
  - 机制层：守卫设计时无「排盘入口穷举清单」，无统一出口静态检查；
  - 历史层：v0.24.0 守卫设计（ADR）只覆盖 AC08 主路径，未把 AI 录入等隐藏入口纳入验收用例。
- **闭环**：编程师 07c7953（doAiParse 统一走 APP.doPaipan + RENDER 守卫纵深防御 + T05 断言 3 条）→ QA 独立 profile 复现重测通过，P0-01 关闭，无新增缺陷。
- **防再发对应**：M2。

### 问题 2：断言数统计口径漂移（TEST 草案 vs QA 验收）— ✅ 已澄清（观察项）

- **事实链**：TEST_v0.24.0 草案写「v0.23.4 基线 232 + 新增 ≥4（T01-T04）」；QA_v0.24.0 最终写「247 = 244 旧 + 3 T05」。232→244 的增量（12 条）在草案中未单列。
- **根因**：验收过程中测试工程师追加了浏览器级断言（并入旧断言统计），但草案未预留增量说明列。
- **处置**：以 QA 最终口径为准（六入口 247 条全绿）；转遗留 R6（TEST 草案明确基线+增量口径）。
- **防再发对应**：M4。

### 问题 3：用户反馈「宫位数据不一致」（跨环境默认值回落）— ✅ 已排查定位（转遗留承接）

- **事实链**：用户公测版（GitHub Pages origin）调过的常用宫位，切内测版（localhost/file:// origin）后看不到 → `loadGroups()` 读不到 localStorage → 静默 `initGongWeiGroups()` 重建默认 14 组 → 观感「数据变了」。
- **根因分层**：
  - 直接层：宫位自定义数据无云端副本、无导出导入，跨 origin 不可见；
  - 机制层：localStorage 按 origin 隔离是浏览器设计，但应用无迁移/备份/提示机制，且 `loadGroups()` 静默重建默认不提示；
  - 历史层：宫位功能（v0.13.0/v0.20.0）从未上云；v0.24.0 账号体系落地时只云化了档案记录，未顺带覆盖宫位配置。
- **处置**：编程师只读排查（零代码改动）确认非版本升级改数据；找回方案 A（手动迁移）/ B（已清空无法找回）/ C（推荐导出导入）；后续迭代保护 5 条建议转遗留 R2-R5。
- **防再发对应**：M5。

### 问题 4：两段式发布期间线上保持旧版（T5 内测 → T6 线上等待授权）— 正常流程，非缺陷

- 内测部署报告明确「线上保持 v0.23.4，T6 待用户另行授权」；用户确认后 T6 完成正式发布。两段式发布隔离了内测/线上，未造成半成品上线。

## 七、经验沉淀

- **守卫设计必须穷举入口清单**：不只包主按钮（APP.doPaipan），AI 录入（doAiParse）、隐私重排（togglePrivacy）、RENDER 直连等隐藏入口都要统一走守卫包装，并用断言（T05）固化——入口不全 = 守卫形同虚设。
- **异步模块测试挂载模式**：同步测试区 + `window.__testAppend` 追加辅助（只追加不重排）是零侵入方案，可复用于任何「异步加载模块的断言追加」场景。
- **localStorage origin 隔离是「数据看起来丢」的高频根因**：跨环境（GitHub Pages / localhost / file://）数据天然不互通；应用层必须提供迁移/备份/提示，禁止静默重建默认（本次宫位回落即此机制）。
- **云端凭证安全三板斧**：anonKey publishable 可公开 + RLS 行级兜底 + 数据库密码/secret 仓库外档案；配合 .gitignore 防呆 + 选择性 git add 双保险。
- **两段式发布（内测等授权 → 正式 tag+Pages）模式成熟**：内测隔离半成品、正式发布前专项验证「修复不丢失」（R3 闭环），可作为后续版本发布标准动作。
- **版本发布链要保留「祖先链完整性」意识**：v0.23.4 修复随 v0.24.0 上线，靠 commit 链继承 + 线上产物专项 grep 验证（lc2Ms/renYuanSiLing），比「看 CHANGELOG 写了」更可靠。
