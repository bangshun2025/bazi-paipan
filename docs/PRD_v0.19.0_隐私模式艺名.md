# PRD v0.19.0 — 隐私模式（艺名）

> 版本：v0.19.0 | 日期：2026-08-09 | 作者：产品经理 (worker_b58a1691)
> 基于：八字排盘 v0.18.0（`standalone-split.html` + 6 模块，构建产物 `standalone.html`）
> 真相源对齐：SYSTEM.md（v0.18.0）

---

## 一、需求背景

邦顺在上八字命理课时，需要打开学员档案做案例讲解，投影/共享屏幕时学员的**真实姓名**会暴露在屏幕上，涉及隐私。

本次新增**隐私模式**：一个全局开关 + 档案第三个名字字段「艺名」。隐私开启时，界面上所有出现真实姓名的位置统一替换为艺名（脱敏名），学员/他人看到的是艺名而非真名；隐私关闭时维持现状。

---

## 二、功能描述

### 2.1 档案新增第三个名字字段「艺名」

- 字段名：`yiming`（与 `nickname`/`name` 拼音风格一致）。
- 主输入表单（`standalone.html` 584 行附近 `input-row`）：在「小名」「姓名」之后新增 `<input id="inYiming">`，标签「艺名」，**选填**。
- 编辑档案弹窗（`standalone.html` 665 行附近 `edit-dialog`）：在「昵称」「姓名」之间（或之后）新增 `<input id="editYiming">`，标签「艺名（选填）」。
- 读写逻辑同步 `getFormData()` / `setFormData()` / `getEditFormData()` / `openEditPanel()` / `saveEdit()`：`yiming: document.getElementById('inYiming').value || ''`。
- 保存到档案对象（localStorage `bz_archives_v2`），字段可选，缺省为空字符串。

### 2.2 新增全局隐私开关

- **默认开启**（首次加载即为隐私模式，防「忘记打开」的泄露风险）。
- 开关状态持久化：`localStorage` 键 `bz_privacy_mode`，值 `'1'`（开启）/ `'0'`（关闭），刷新/重开保持。
- 开关为**全局**：影响所有档案显示 + 排盘标题，一处切换全局生效。

### 2.3 隐私模式下的显示规则（核心逻辑）

统一收敛为一个显示函数（替代散落的 `displayName` 拼装）：

```
getDisplayName(a)：
  if 隐私关闭 → 维持现状：(a.nickname ? a.nickname + ' / ' + a.name : a.name)
  if 隐私开启 → 降级链：a.yiming → a.nickname → '匿名'
```

**隐私模式铁律：任何显示点都不得出现 `a.name`（真名/正名）字段，包括姓氏。**

## 三、决策点结论

### 决策 1：隐私模式下显示格式 → **只显示「艺名」**

| 方案 | 结论 | 理由 |
|------|------|------|
| A. 只显示「艺名」 | ✅ **推荐** | 隐私目标最彻底；屏幕干净；艺名由邦顺自定，可控 |
| B. 显示「小名 / 艺名」 | ❌ 不推荐 | 小名虽是课堂称呼，但 16 孩预置档案的小名学员/家长互相知晓，小名+出生日期仍可定位到具体学员，脱敏不彻底 |

补充：若隐私模式下仅显示艺名，则正常模式「小名 / 正名」与隐私模式「艺名」构成对称：**正常模式看小名，隐私模式看艺名**，两个模式都不暴露中间态，心智清晰。

### 决策 2：艺名未填写时的降级策略 → **降级链：艺名 → 小名 → 「匿名」**

| 方案 | 结论 | 理由 |
|------|------|------|
| A. 降级显示小名 | ✅ **推荐** | 小名是课堂既有称呼，老师讲解可指代；小名不构成全名，相对安全 |
| B. 显示「小名+姓氏」脱敏 | ❌ 不推荐 | 姓氏是真实身份一部分，脱敏不彻底；格式复杂 |
| C. 一律显示「匿名」 | ❌ 不推荐 | 完全失去辨识度，邦顺讲课自己都分不清是谁 |

- 艺名 → 小名 → 「匿名」三级降级，**任何情况下不回退到真名**。
- 「匿名」文案建议固定为「学员」更贴合课堂场景（可选，实现时定）。

### 决策 3：开关位置与持久化 → **主输入区工具行（主入口）+ 档案面板顶部（同步开关），localStorage 持久化，默认开启**

| 方案 | 结论 | 理由 |
|------|------|------|
| A. 主输入表单工具区（与「📋档案」「♻️」同排） | ✅ **主入口** | 隐私影响排盘标题+档案显示，排盘是主界面；上课前一眼可见、一键确认 |
| B. 档案面板顶部工具区（搜索行右侧） | ✅ **同步开关** | 语义贴合「看别人信息」场景；两处同一状态 |

- 样式建议：`🔒 隐私`（开启）/ `🔓 隐私`（关闭）按钮式 toggle，开启态高亮。
- 持久化理由：邦顺每次上课都要隐私模式，若刷新后回默认关闭，忘开即泄露。**默认开启 + 持久化**双保险。

### 决策 4：涉及显示点替换清单（全部出现真实姓名的位置）

| # | 显示点 | 代码位置（模块版） | 隐私模式行为 |
|---|--------|--------------------|--------------|
| 1 | 档案列表行 | `archive.js` renderArchiveModal（standalone.html 3045 行附近 `displayName` 拼装） | 显示 `getDisplayName(a)`（艺名/小名/匿名） |
| 2 | 档案搜索结果行 | `archive.js` filterArchives（同一 `displayName` 拼装逻辑） | 同上 |
| 3 | 普通排盘标题 | `render.js` 549 行 `person-info <b>${name}</b>` | 显示当前排盘人脱敏名 |
| 4 | 同性双胞胎排盘标题 | `render.js` 1110 行 `person-info <b>'+name+'</b>` | 同上 |
| 5 | 龙凤胎排盘标题 | `render.js` renderLongFengCardsHtml（L1129 `name = d1.name`；L1219 `person-info <b>'+name+'</b>`） | **需脱敏**：顶部 person-info 显示 `getDisplayName(d1)`；「老大/老二」卡片标签（`buildCardHTML` label）保留不脱敏 |
| 6 | 删除档案确认弹窗 | `archive.js` moveToTrash `确定删除「a.name」` | 隐私开启时显示脱敏名 |
| 7 | 覆盖档案确认弹窗 | `archive.js` saveArchive `「d.name」已存在` | 隐私开启时显示脱敏名 |
| 8 | AI 录入解析预览 | `main.js` 490 行 `姓名：r.name` | 隐私开启时预览显示「姓名：已隐藏」 |
| 9 | 主输入表单 `inName` 输入框 | `standalone.html` 585 行 | **不脱敏**（老师操作视角，自己输入需看到真名；见「非目标」） |
| 10 | 编辑弹窗 `editName` 输入框 | `standalone.html` 668 行 | **不脱敏**（老师维护数据视角，需看到真名才能编辑；上课投影时应避免打开，见「风险提示」） |

> 搜索匹配字段（`filterArchives`）需同步加入 `yiming`，否则按艺名搜不到档案（#2 连带）。
>
> **勘误（v1.1）**：初版 PRD 曾称「龙凤胎视图不显示姓名、无需改动」，经架构师复核（render.js L1219 `person-info <b>'+name+'</b>`，name = d1.name）修正为**需纳入脱敏**。实现时 renderLongFengCardsHtml 顶部标题改用 `getDisplayName(d1)`。

### 决策 5：旧档案数据兼容 → **结构不变、字段可选、零迁移**

- 旧档案对象无 `yiming` 字段 → 读取时 `a.yiming || ''` 自然兼容，`undefined` 视为空。
- localStorage 键 `bz_archives_v2` **不变**（新增可选字段向后兼容，无需迁移脚本）。
- 隐私模式下旧档案：艺名为空 → 走降级链（小名 → 「匿名」），行为确定。
- 预置档案 16 孩：**不强制**批量补艺名，邦顺后续在编辑弹窗按需补充；降级链兜底。
- `PRESET_ARCHIVES` 数据源本身含真名属正常（数据层），仅显示层脱敏。

## 四、交互细节

1. **开关交互**：点击切换 `bz_privacy_mode`（1↔0），立即重渲染档案面板（若开着）与当前排盘标题；刷新保持。
2. **艺名输入**：主表单与编辑弹窗均可填写/修改；保存后进入档案对象。
3. **排盘流程**：`doPaipan()` 内部保持 `data.name` 为真名（数据层不动），渲染前用 `getDisplayName` 替换显示层 `name`。档案保存仍存真名，不因隐私模式改变数据。
4. **档案列表/搜索**：`renderArchiveModal` / `filterArchives` 中 `displayName` 拼装替换为统一 `getDisplayName(a)` 调用。
5. **视觉提示**：隐私开启时建议在档案面板标题或开关旁显示「隐私模式」小字提示，明确当前状态（防止邦顺误以为关了/开着）。

## 七、非目标（明确不做）

- **不脱敏**主输入表单 `inName` / 编辑弹窗 `editName` 输入框内的真名（老师维护数据需看到真名；上课操作者是邦顺本人，输入框非展示面）。
- 不做「每档案单独隐私设置」（本次为全局开关）。
- 不做「艺名自动生成/随机」。
- 不做「导出/截图水印」等延伸能力。
- 不改动档案数据存储结构（`bz_archives_v2` 键不变，仅加可选字段）。

## 八、测试要点

### 8.1 边界 case

- 艺名 = 空字符串、纯空格（trim 后视为空）。
- 小名 = 空、艺名 = 空 → 「匿名」占位。
- 旧档案 `yiming` 为 `undefined`（读取兼容）。
- 双胞胎模式（`inTwin=1`）与龙凤胎（`inTwin=2`）下标题脱敏一致性（龙凤胎顶部 person-info 必须脱敏，卡片标签「老大/老二」保持）。
- 搜索关键词同时命中真名/小名/艺名时的匹配与显示。

### 8.2 回归风险点

- 档案列表正常模式显示格式与 v0.18.0 逐字一致（隐私关闭时零变化）。
- 16 孩预置档案排盘结果不受影响（数据层不动）。
- 构建产物同步：`standalone.html` 与 6 模块一致性（跑 `build_modules.py`）。
- `?test=1` 199 条自动断言回归通过，新增隐私相关断言。
