### **P2 — 1 项：D-01「真实设备视口高 <773px 时 AC20 未达成」（存疑项）**

**（1）现象**：真实浏览器窗口（非 Emulation）下，若**视口高 `innerHeight` < 773px**，打开「星曜设置页」空查询 60 行态时 `.xy-settings-body` 出现纵向滚动条，`scrollHeight - clientHeight = 15px`（1440×900 屏）／`107px`（1280×800 屏）／`136px`（1366×768 屏）；且内置套件 T12 在口径 C 下由绿变红。

**（2）判据依据**：PRD r7 **E21**「视口较矮但仍 ≥1280px 宽（如 1280×800）→ 优先保住「无纵向溢出」，允许压缩行高/字号（92vh 预算见 FR3.6）；**若仍溢出，须记为未达成 AC20 的存疑项，不得用滚动假装通过**」。

**（3）根因（代码级，已确证）**：
- `.xy-settings-modal { max-height: 92vh }`（`index.html:244–245`，**本版引入**，见 (5)）在 `innerHeight < 773px` 时成为**瓶颈**：实测 `getComputedStyle(modal).maxHeight` = `696.44px` @innerH 757 = `0.92 × 757` —— **弹层高度正好等于 92vh**，即 max-height 生效并压住了内容。
- `.xy-settings-body { flex:1; overflow-y:auto }`（`index.html:254`）随之滚动。
- **阈值 = 内容自然高 711px ÷ 0.92 ≈ 772.8px 视口高**。`innerHeight ≥ 773` ⇒ 弹层取内容高 711px、`dH=0`；`< 773` ⇒ 弹层被压到 92vh、`dH > 0`。
- **在 PRD 视口口径（Emulation 1440×900，innerH=900）下 `92vh = 828 > 711`，max-height 不触发** ⇒ 这也是「视口口径全绿、真实窗口口径变红」的机制原因。

**（4）① 15px 究竟切掉了什么（Leader 指定必答项，实测 `evidence/clip_probe.json`）**：

| 真实窗口 | innerH | clipped | modalH（=92vh） | 页脚 | body client←scroll | 完整可见行 | 被裁内容 |
|---|---|---|---|---|---|---|---|
| 1440×900 | 757 | **15px** | 696.44 | ✅ 可见（54px） | 555 ← 570 | **57 / 60** | 三栏末行各露 15px、**裁 7px**（共 3 行不完整） |
| 1280×800 | 657 | **107px** | 604.44 | ✅ 可见 | 463 ← 570 | **45 / 60** | 每栏末 **5 行**不可见（末行裁 99px） |
| 1366×768 | 625 | **136px** | 575 | ✅ 可见 | 434 ← 570 | **42 / 60** | 每栏末 **6 行**不可见（末行裁 128px） |

**裁决依据**：**被裁掉的是「行」，不是留白/页脚**（页脚 `footVisible=true` 完整可见；`.xy-settings-modal` 三段式 = 头 50px + 滚动体 + 脚 54px，页脚在滚动体之外）。
- 1440×900 真实窗口：被裁 = 三栏末行（癸未 / 癸卯 / 癸亥）底部 **7px**（该行高 22px，露出 15px）—— 截掉的是该行**下内边距/下边框**，**文字本体仍在可视区内**；
- 1280×800 / 1366×768：被裁 **99–128px** ⇒ 每栏末 **5–6 行整体不可见**，须滚动。
⇒ **按 Leader 判据「若裁掉行 ⇒ P2」**，故本项定 **P2**（不阻断：数据/操作均可用，仅需滚动；且 PRD 基线口径判据通过 + E21 提供留痕出口）。

**（5）② 归属判定（必须有证据，禁止凭印象）**：

| 项 | v0.29（上一版） | **v0.30（本版）** | 证据 |
|---|---|---|---|
| 弹层上限 | `max-width:720px` + **`max-height:85vh`** | `width:90vw; max-width:1200px;` + **`max-height:92vh`** | **PRD r7 L287 原文**：「`.xy-settings-modal` **由 `max-width:720px; max-height:85vh` 改为 `width:90vw; max-width:1200px; max-height:92vh;`**」；L494 改动清单同述 |
| 布局 | 单栏 60 行 | 三栏（`@media (min-width:1280px)` Grid）+ 搜索栏 + 纳音列 | PRD r7 FR3.4 / L494 |
| **内容自然高** | 单栏：`scrollHeight = 1504px`（实测于 1279×800 / 768×900 / 390×844，媒体查询未生效的单栏态） | 三栏：`scrollHeight = 570px` | `qa_measure_idx.json`：单栏档 `scrollH 1504`；宽屏档 `scrollH 570` |

**结论**：`max-height` 机制本身**既有**（v0.29 为 85vh），但 **92vh 是本版把 85vh 放宽而来、是新增值**；**且本版真正做的事是把内容自然高从 ≈1504px 压到 570px（−934px，约 −62%）**。
⇒ 因此 **不能写成「既有机制的暴露」**，准确表述是：**本版新增的弹层契约（92vh）在真实窗口口径下的边界残差**；同时本版相对 v0.29 **明确是净改善**（v0.29 在 1440×900 真实窗口下 85vh=643 < 1504，必然大幅滚动；本版同条件下仅 15px）。
（诚实标注：上表 v0.29 行内容高用「当前单栏态 1504px」作量级代理 —— v0.29 无搜索栏/纳音列，故真实值略有差异，仅用于量级对比。）

**（6）③ 双口径必须并列写清（防后人误读）**：

| 口径 | 「1440×900」的含义 | 实测 innerHeight | modal 上限 | body `dH` | T12/AC20 |
|---|---|---|---|---|---|
| **PRD 视口口径**（判据基准） | **视口尺寸** | **900** | 92vh = 828（**不触发**） | **0** | ✅ 通过 |
| **真实窗口口径** | **窗口尺寸** | **757** | 92vh = 696.44（**触发**） | **15** | ❌ 未达成 → D-01 |

PRD r7 L24「验收视口主基线 **1440×900**，另抽 **1280×800** / **1600×1000**」+ L289「**900px 高视口** → `92vh=828px`；扣标题栏+搜索栏+页脚+内边距≈180px ⇒ 表区~648px；合计~570px，余量~78px」⇒ **PRD 的高度预算口径确定是「视口尺寸」**，不是屏幕分辨率、也不是浏览器窗口尺寸。

**（7）④ 本版不修 D-01（Leader 裁定，理由留档）**：缓解手段都会触碰**已冻结口径** —— 「压缩行高/字号」触碰 PRD 的版面规定，「放宽 `max-height`」触碰 ADR 的弹层契约，二者均会触发 PRD/ADR 升版与引用级联；而本版已被用户指定为**发布优先**。⇒ 记为 **P2 存疑项** + 向用户如实报告，**是否单开一轮小修由用户拍板**。

## 十、方法论留痕（供交接与复盘）

1. **证伪 Leader 假设的过程**：Leader 原假设为「15px = 测试横幅人造溢出」。测试侧用**无横幅真实用户态**（`?test=1` 不带、实测 `hasTestUI=false`、手工打开登录门）取证，结果与带横幅态**完全一致（同为 15px）** ⇒ 假设被**证伪**；随后逐步排除「横向滚动条（`dW=0`）」「字体度量差（`rowH=22.000` 两口径一致）」，锁定真根因（`max-height:92vh` vs 内容自然高 711px）。
2. **两个假量陷阱**（见 §2.1）：未排盘态 `.page{display:none}` 致 CDP 全 0；`?test=1` 横幅污染视口/宽度量。**凡涉及视口高与页面级溢出的量，必须用无横幅真实态。**
3. **口径必须写明**：Emulation **视口口径** ≠ `--window-size` **真实窗口口径**（分辨率 1440×900 → 窗口 1440×900 → `innerHeight` 757）。报告中任何「1440×900」必须标注是哪一种，否则结论会互相矛盾。
4. **不采信自证**：编程师/PM/架构师给出的数值仅作旁证，全部由测试侧独立复测（C8 逐档、N6、三条红线、双副本 md5、check-release 双容器）。
