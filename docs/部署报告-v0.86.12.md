## 背景

v0.86.10（commit `2c53746`）上线「出生数据护栏」：写「盘面-*.md」前比对旧文件出生行，变更先把旧盘面备份进「历史/」再覆盖（SN26 六条断言）。护栏真目录 E2E 实测中发现**新建档案同步回归 bug**，本轮两连修修复并重新发布。

## Bug 根因与修复

### Bug 1（v0.86.11 修）：getFileHandle NotFoundError 挂穿同步链

- 现象：新建档案后每次全量同步 `syncAll()` 返回 0，「盘面-新档案.md」永不落盘，提示「同步失败」
- 根因：`syncBirthGuardWrite` 里 `dir.getFileHandle(name)` 未带 `{create:true}`，磁盘不存在的文件（新档案首次写）直接 NotFoundError 拒绝；而 `.catch` 挂在内层 `fh.getFile()` 读链上护不住外层，拒绝穿透 → syncAll 逐文件 Promise 链整链 reject → catch return 0。v0.86.10 首次同步 167 成功是因为当时测试档案还没建档
- 修复：catch 上提一层罩住「getFileHandle→getFile→读旧文」整链，读不到（含文件缺失）→ oldText='' → 护栏判 null → 跳过备份 → `syncWriteOne`（自带 create）正常写新文件。语义完全保留「读不到旧文件就跳过备份」
- commit `08abb9f` + tag `v0.86.11`

### Bug 2（v0.86.12 修）：syncSubDir 空子目录名

- 现象：v0.86.11 发布后线上 E2E 发现 syncAll=168 全部写成功，但 `syncReadText('', '盘面-*.md')` 恒读不到（连根目录 INDEX.md 也读不到）
- 根因：`syncSubDir('')` 对空名调 `_syncDir.getDirectoryHandle('', {create:true})`，Chrome 抛 TypeError → catch 返回 null → 所有根目录读操作静默返回 null
- 修复：`if (!sub) return Promise.resolve(_syncDir)` 空名直接返回根目录句柄
- commit `fb1f357` + tag `v0.86.12`
