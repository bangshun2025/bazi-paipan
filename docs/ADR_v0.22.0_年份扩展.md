## 一、架构决策

### 决策 1：数据生成策略——全量重生 vs 增量追加

**问题**：v0.21.0 采用「前置插入」策略（1600-1899 新数据 + 1900-2100 旧数据逐字不动）。v0.22.0 扩展到 1000 年后，是继续前置插入还是全量重生？

**选项**：

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. 前置插入 | 生成 1000-1599 数据，插入到现有数据头部 | 旧数据不动，1900-2100 逐日结果不变 | 数据量 2.3 倍，两段式维护成本高；1000-1599 与 1600-2100 数据源可能不同 |
| B. 全量重生 | sxtwl 统一生成 1000-2100 全部数据，替换三张表 | 数据源统一，可交叉验证；消除历史数据源差异隐患 | 1900-2100 段可能与旧数据有微小差异（秒级） |

**决策**：选择 **方案 B——全量重生**。

**理由**：
1. SOLAR_TERMS 从 12024 膨胀到 26424 条，维持「两段式」数据的维护成本急剧上升
2. 统一数据源后，所有年份可交叉验证，数据质量审计变为可能
3. 现有回归测试 `?test=1` 的断言覆盖了关键排盘结果——全量重生后若断言失败，反而是好事（发现历史数据问题并一次性修正）
4. 秒级差异不影响八字排盘（月柱按日级判断、日柱按午夜 0 点、时柱按奇数整点）

**后果**：
- v0.21.0「逐日一致」承诺变为「与 sxtwl 输出一致」
- 实施第一步必须是：用 sxtwl 生成 1600-2100 段，与现有 constants.js 逐项比对差异清单，供邦顺确认

---

### 决策 2：大运分级策略——1400 年分界线

**问题**：1000-1399 年 sxtwl 节气精度下降（ΔT 不确定性导致数分钟至数十分钟误差），起运计算 `qiYunDays()` 精确依赖节气时刻，误差会被放大。是否仍然显示大运？

**选项**：

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. 强制显示大运 | 1000-2100 全线起大运 | 功能一致 | 1000-1399 大运可能不准，损害信任 |
| B. 分级大运 | ≥1400 正常起大运，<1400 不显示大运 | 不输出不可靠结果 | 需适配空大运 UI |
| C. 低精度补偿 | 对 1000-1399 降低精度要求，仍然起大运 | 功能覆盖完整 | 用户不知道哪个大运可靠、哪个不可靠 |

**决策**：选择 **方案 B——分级大运**。

**理由**：
- 给错误大运比不给大运更损害信任
- 四柱不受影响（年柱仅依赖立春日期≈日级精度，月柱仅依赖节气日期≈日级精度，日柱仅依赖公历日期计数=完全精确）
- 流年不受影响（`(y-4)%60` 纯数学公式）
- 1400 年是 JPL DE440s 星历在 sxtwl 中可用的可靠下限

**后果**：
- `computeDaYun` 增加 `< 1400` 提前返回
- render.js 需 4 处守卫适配 `daYun.length === 0` 和 `qiYun === null`
- 流年/四柱区 UI 不受影响

---

### 决策 3：文件同步机制——沿用 v0.21.0 模式

**决策**：沿用 v0.21.0 的三文件同步机制，不做改变。

```
外部 JS（编辑入口）         内联 HTML（发布产物）
constants.js      ──同步──→ index.html（内联 constants 段）
algorithm.js      ──同步──→ index.html（内联 algorithm 段）
render.js         ──同步──→ index.html（内联 render 段）
archive.js        ──同步──→ index.html（内联 archive 段）
                                       │ cp
                                       └──→ standalone.html
standalone-split.html（外部引用版，仅改 HTML 属性）
```

**同步说明**：
- index.html 内嵌了 4 个 JS 文件的内联版本（`<script>` 标签内），行数随 JS 文件增长
- standalone.html 与 index.html 字节级一致，`cp index.html standalone.html` 即可
- standalone-split.html 通过 `<script src="...">` 引用外部 JS，故只需改 HTML 属性（min/max/错误文案），数据更新通过外部 constants.js 自动生效

## 五、数据质量评估

### 5.1 sxtwl 对 1000-2100 各段的精度

| 年份段 | ΔT 不确定性 | 节气精度 | 大运可信度 |
|--------|:---:|:---:|:---:|
| 1900-2100 | ~±10 秒 | **秒级** | ✅ 完全可信 |
| 1600-1899 | ~±120 秒 | **±2 分钟** | ✅ 可信（时辰精度 ±1 小时） |
| 1400-1599 | ~±300 秒 | **±5 分钟** | ✅ 可信 |
| 1000-1399 | ~±600-1800 秒 | **±10-30 分钟** | ❌ 不可信——因此隐藏大运 |

### 5.2 全量重生的差异化影响

**关键问题**：如果旧 1900-2100 数据源 ≠ sxtwl，全量重生后会有差异。

**影响分析**：
- 差异最可能出现在节气时刻（秒级），不影响月柱
- 个别农历年的大小月排列（极罕见）
- `?test=1` 的断言值可能需要更新

**缓解措施**：实施第一步——生成 1600-2100 段后与现有 constants.js 逐项比对，列差异清单。

### 5.3 历史人物锚点验证

PRD 已确认 4 个锚点（苏轼/朱熹/文天祥/王阳明）均可用 sxtwl 正确排盘。实施阶段需用生成的数据逐一验证。
