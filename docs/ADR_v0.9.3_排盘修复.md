## 3. 确认Bug：人元司令 丑月年份偏移

### 3.1 现象

**妍语 (#16)**：女，2020-01-20 00:00。司令返回空字符串，期望「己」。

### 3.2 根因定位

**文件**: `standalone.html`
**函数**: `renYuanSiLing(y, m, d)`
**Bug行**: 第 1640 行

```javascript
// 当前代码 (Bug)
const stY = (termIdx === 0 && mi === 11) ? y + 1 : y;
```

**逻辑错误**：对于丑月（mi=11，termIdx=0=小寒），代码一律给 `y+1`。但 1 月出生者的丑月小寒在同一年 `y`，不应 +1。

以妍语为例：
- 出生：2020-01-20，处于 2020年丑月（小寒 2020-01-06 → 立春 2020-02-04）
- Bug行为：stY = 2020+1 = 2021，查找 2021年小寒（≈2021-01-05）
- 结果：2020-01-20 < 2021-01-05，不在任何月份区间，返回空字符串 `''`

**为什么月柱没受影响？**
`monthPillar()` 有同样的年份逻辑，但它在遍历完所有月份后有一个 fallback 直接返回丑月（代码第1323行），所以月柱通过兜底逻辑得到了正确结果。而 `renYuanSiLing()` 没有 fallback，直接返回空字符串。

### 3.3 影响范围

- **直接影响**：所有 1 月出生且处于丑月的孩子。本批次仅妍语一人（唯一1月出生的孩子）。
- **间接影响**：无连锁影响。四柱、胎元、命宫、身宫、大运均不依赖司令计算。

### 3.4 修复方案

**推荐方案（最小改动）**：

```javascript
// 修复后代码
let stY = y;
if (termIdx === 0 && mi === 11) {
  // 丑月（小寒）：判断出生是否在1月
  // 1月出生→小寒在同一年y；其他月份→小寒在y+1
  stY = (m === 1) ? y : y + 1;
}
```

**改动位置**: `standalone.html` 第 1640 行，仅替换一行。
**改动量**: 1 行 → 5 行。
**风险评估**: 低。仅影响丑月小寒的年份判定，逻辑清晰。

### 3.5 验证方法

修复后对妍语重新排盘，司令应返回「己」。对所有16孩重新跑批，确认无新增差异。

## 4. 待确认项 A：双胞胎 KK 大运方向

### 4.1 现象

| 孩子 | 性别 | 年柱 | 大运方向 | 首运(算法) | 首运(参考) |
|------|------|------|----------|-----------|-----------|
| NONO | 男 | 己亥(阴) | 逆排 | 癸酉 ✓ | 癸酉 |
| KK | 女 | 己亥(阴) | 顺排 | 乙亥 | 癸酉 ✗ |

NONO 和 KK 是龙凤双胞胎，同八字（己亥 甲戌 戊子 丁巳），性别不同。

### 4.2 分析

`computeDaYun()` 的顺逆规则（标准八字规则）：
```
阳年(甲丙戊庚壬)男 → 顺排
阴年(乙丁己辛癸)男 → 逆排
阳年女 → 逆排
阴年女 → 顺排
```

- NONO (男 + 己年阴): 逆排 ✓ → 甲戌逆数1位 = 癸酉 ✓
- KK (女 + 己年阴): 顺排 → 甲戌顺数1位 = 乙亥

**算法行为符合标准八字规则。**

但参考数据中 KK 的首运为「癸酉」，与 NONO 相同（即也按逆排）。

### 4.3 判断

两种可能：
1. **参考数据有误** — KK 应顺排，首运乙亥。算法正确。
2. **特殊业务规则** — 双胞胎共享大运方向（某些流派做法），此时需在代码中加入双胞胎特殊逻辑。

**建议**：向邦顺确认业务规则：龙凤胎是否共享大运方向？若共享，则需修改 `computeDaYun` 中的性别判断逻辑。

### 4.4 如需修复

若确认龙凤胎共享大运方向，修改 `computeDaYun` 函数（第1580行），增加双胞胎参数：

```javascript
// 增加 twinMode 参数：true 时双胞胎统一用老大的方向
function computeDaYun(gender, nianGan, yueGan, yueZhi, birth, twinMode) {
  const yang = '甲丙戊庚壬'.includes(nianGan);
  const male = gender === '男';
  let shun = (male && yang) || (!male && !yang);
  if (twinMode && gender === '女') {
    // 龙凤胎老二与老大同方向
    shun = !shun;
  }
  // ... rest unchanged
}
```

## 5. 待确认项 B：妍语身宫天干

### 5.1 现象

**妍语 (#16)**：身宫 期望「戊寅」→ 算法得「丙寅」。地支一致（寅），天干不一致（丙 vs 戊）。

### 5.2 分析

```
入参: yueZhi=丑, shiZhi=子, nianGan=己

dzNum(丑)=12, DZ.indexOf(子)=0
n = (12+0+1) % 12 = 1  →  numZhi(1) = 寅 (地支 ✓)

天干: WU_HU_DUN[己]=丙, TG.indexOf(丙)=2
offset = n-1 = 0
gan = TG[2+0] = 丙  →  身宫 = 丙寅
```

15/16 孩子的身宫完全匹配，仅妍语一人天干不符。

### 5.3 判断

- 地支计算一致（寅），说明身宫地支公式在妍语 case 也正确
- 天干使用五虎遁（年上起月），己年寅月 = 丙寅，逻辑一致
- 只有这一个孩子出现天干偏差，**高度怀疑参考数据录入错误**（应为丙寅，误写为戊寅）

**建议**：人工复核妍语的身宫，确认参考值是否正确。

## 6. 非Bug差异说明

### 6.1 糯米 (#6) — 司令「甲」vs「己」

- 糯米: 2020-08-06，处未月（2020年小暑7月6日→立秋8月7日），节后第31日
- 未月司令表: `[[9,'丁'],[12,'乙'],[30,'己']]`，节后31日 → 己司令
- **未月司令表中无「甲」**，算法返回「己」符合司令表
- **参考数据「甲」很可能是录入笔误**

### 6.2 想想 (#7) — 司令「戊己」vs「戊」

- 想想: 2019-08-09，处申月（立秋8月7日→白露9月7日），节后第2日
- 申月司令表: `[[7,'戊'],[14,'壬'],[30,'庚']]`，节后2日 → 戊司令 ✓
- 参考数据「戊己」是双司令表述法，可能指代申月与未月交替时的司令
- **这不是算法Bug，是显示格式差异**（算法仅返回当前司令单字）
