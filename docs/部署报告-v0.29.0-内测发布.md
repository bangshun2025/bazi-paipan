## 六、本次缺陷修复（E1）· 独立章节

### 6.1 缺陷现象（发布师在收尾复验时发现）
- `GET /api/ext/bazi-paipan/xingyao.js` → **HTTP 404**（`{"error":"no route for GET /api/ext/bazi-paipan/xingyao.js"}`）
- `GET /api/ext/bazi-paipan-test/xingyao.js` → **HTTP 404**
- `standalone-split.html:966` 已新增 `<script src="xingyao.js"></script>`，但该模块**无法被服务端路由命中**。
- 影响面：内测容器 launcher 条目 url = `/api/ext/bazi-paipan-test/standalone`（即 `standalone-split.html`）→ 浏览器加载 `xingyao.js` 失败，`window.XINGYAO` 缺失；`render.js` 中 `window.XINGYAO`（render.js:221/224/267）与工具栏「星曜」按钮 `onclick="XINGYAO.openSettings()"`（render.js:740/1324/1435）失效 ⇒ **模块版星曜设置不可用**（单体版 `index.html` / `standalone.html` 因内联不受影响）。
- 因内测 launcher 走的就是 standalone-split 入口，「模块版星曜不可用」= 本功能在内测环境未真正交付 → Leader 裁决 **不可记为已知限制放行**。

### 6.2 根因
`api/handler.rb` 第 717 行的静态 JS 模块白名单（服务端路由注册表）**漏登记新模块 `xingyao.js`**：
```ruby
# 修复前（717 行）
```
